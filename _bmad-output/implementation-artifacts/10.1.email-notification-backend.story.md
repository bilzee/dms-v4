# Story 10.1: Email Notification Channel Backend

## Status
Ready

## Story
**As a** user,
**I want** to receive email notifications for high-priority action signals,
**so that** I am alerted even when I am not actively using the application.

## Acceptance Criteria

1. **Email config extension** - `NotificationConfig` type extended with `emailEnabled: boolean`, `emailPriorities: SignalPriority[]`, `emailDigestEnabled: boolean`, `emailDigestTime: string`
2. **Config persistence** - New fields stored in `SystemSetting` under `notification` section, loaded/saved via existing `notification-config.service.ts`
3. **Email gate function** - `shouldSendEmail(priority, config)` returns true when email is enabled and priority is in `emailPriorities`
4. **Email notification sending** - When `upsertSignal()` creates a new signal, if `shouldSendEmail()` is true, an email is sent to the signal's user using `EmailService`
5. **Email template** - HTML email rendered from `NOTIFICATION_TEMPLATES` with entity name, signal reason, priority badge, and deep link to dashboard
6. **User email lookup** - Email sent to `User.email` of the signal's `userId`; skipped if user has no email
7. **Unsubscribe endpoint** - `GET /api/v1/notifications/unsubscribe?token={hmacToken}` disables email notifications for that user, returns confirmation page
8. **Unsubscribe token** - HMAC-SHA256 of `userId` using server secret; verified on unsubscribe
9. **Error resilience** - Email send failures are logged but do not block signal creation
