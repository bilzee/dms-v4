# Story 10.3: Daily Email Digest Job

## Status
Ready

## Story
**As a** user,
**I want** to receive a daily digest email summarizing my active signals instead of individual emails for each signal,
**so that** I am not overwhelmed by frequent email notifications for non-critical signals.

## Acceptance Criteria

1. **Digest collection** - Job queries all users with `emailDigestEnabled=true` and collects their unresolved signals created in the last 24h
2. **Digest email template** - HTML email with a summary table: signal reason, entity name, priority badge, time created, link to dashboard
3. **Digest grouping** - Signals grouped by entity in the email, with entity-level section headers
4. **Digest time respect** - Job respects `emailDigestTime` per-user setting; signals are only sent at the configured time
5. **API endpoint** - `POST /api/v1/jobs/email-digest` triggers the job; protected by admin or internal secret
6. **Individual email suppression** - When digest is enabled for a user, `sendEmailNotification()` in `upsertSignal()` skips CRITICAL signals only (CRITICAL always sends immediately); non-CRITICAL are queued for digest
7. **Empty digest skip** - If a user has no new non-CRITICAL signals in 24h, no email is sent
8. **Error resilience** - Per-user send failures are logged and do not abort the job for other users

## Tasks / Subtasks

- [ ] **Task 1: Digest Job Service** (AC: 1, 4, 7, 8)
  - [ ] Create `src/lib/jobs/email-digest.ts`
  - [ ] `runEmailDigest()` function:
    - Query `SystemSetting` for users with `emailDigestEnabled=true`
    - For each user: query `ActionSignal` where `userId = ? AND resolvedAt IS NULL AND priority NOT IN ('CRITICAL') AND createdAt >= now() - 24h`
    - If no signals, skip (AC 7)
    - Group signals by `entityId`, join `Entity` for name
    - Render digest email, send via `emailService.send()`
    - Try/catch per user, log errors, continue (AC 8)

- [ ] **Task 2: Digest Email Template** (AC: 2, 3)
  - [ ] Create `src/lib/email/digest-email-template.ts`
  - [ ] `renderDigestEmail(params: { userName, signalsGroupedByEntity, dashboardUrl })` → `{ html, text }`
  - [ ] HTML: greeting, summary stats (X signals across Y entities), per-entity sections with signal table rows
  - [ ] Each row: signal reason label, priority badge (colored), time ago, "View" link
  - [ ] Footer: unsubscribe link, "You received this because you enabled email digest"
  - [ ] Text: same content in plain text

- [ ] **Task 3: API Endpoint** (AC: 5)
  - [ ] Create `src/app/api/v1/jobs/email-digest/route.ts`
  - [ ] `POST` handler: validate `Authorization: Bearer {INTERNAL_JOB_SECRET}` or admin role
  - [ ] Call `runEmailDigest()`, return `{ success: true, sentCount, skippedCount, errorCount }`

- [ ] **Task 4: Suppress Individual Emails for Digest Users** (AC: 6)
  - [ ] In `action-signal.service.ts` `sendEmailNotification()`:
    - Load user's notification config
    - If `emailDigestEnabled` is true AND signal priority is NOT CRITICAL: skip individual email (will be sent in digest)
    - CRITICAL signals always send immediately regardless of digest setting

- [ ] **Task 5: Unit Tests** (AC: 1, 2, 6, 7)
  - [ ] `tests/unit/jobs/email-digest.test.ts`
  - [ ] Test digest collection filters correctly (only non-CRITICAL, unresolved, last 24h)
  - [ ] Test empty digest skip (no email sent when 0 signals)
  - [ ] Test individual email suppression when digest enabled
  - [ ] Test CRITICAL signals bypass suppression

## Technical Notes
- Job scheduling: intended to run via external cron (Dokploy scheduled task or system cron) calling `POST /api/v1/jobs/email-digest` every hour
- The job checks each user's `emailDigestTime` and only sends if current hour matches (allows staggered delivery)
- `INTERNAL_JOB_SECRET` env var used for endpoint auth (same pattern as existing reconciliation job)
- Follows pattern of existing `src/lib/jobs/signal-reconciliation.ts`
