⚙ Differences Summary — VerificationQueue
  • Severity tint provides instant visual priority cue. Each card gets a left-border color and background tint based on getSeverity() (CRITICAL = red, HIGH = amber, MEDIUM = blue). The current implementation has no visual differentiation until you read the badge.
  • Unified expand/collapse behavior. DataCardList manages expanded state internally via expandable=true with renderExpanded. The current component manually tracks expandedItems: Set<string> with a toggle handler.
  • Consistent card padding and spacing. All cards follow the same internal layout contract from DataCardList, eliminating ad-hoc cn() class merging per card.
  • Standard SearchToolbar integration. Search + filters are composed in a single toolbar row rather than a custom flex layout with individual Select and Input components.
  • Standard PaginationBar component. Replaces the hand-built "Showing X-Y of Z" + Previous/Next buttons with a consistent <PaginationBar />.
  • Selected state preserved. The ring-2 ring-blue-500 highlight from the current implementation maps directly to DataCardList's built-in selection support.
  • Removed inline styling and manual cn() calls for per-card padding, hover shadow, and transition classes -- all handled by the DataCardList container.

⚙ Differences Summary — IncidentManagement
  • Unified SearchToolbar with FilterConfigs. The current component has a dedicated Card with a 4-column grid for filters. DataTable replaces this with a single <SearchToolbar> row plus declarative FilterConfig[] definitions (type, status, severity, date).
  • Expandable rows via ColumnDef. Instead of manual expandedRows: Set<string> state and colSpan detail rows, DataTable uses expandable=true with a renderExpanded callback that receives the row data.
  • Row actions via DropdownMenu. The current inline Edit/Delete buttons are replaced by actions=[{label:"Edit", ...}, {label:"Delete", destructive:true}] rendered as a standard DropdownMenu in the last column.
  • Expanded section gets a branded top border. The target uses a primary-colored top border on the expanded detail panel, giving visual consistency with the chevron toggle state.
  • SafeDataLoader retained externally. The DataTable itself handles loading/empty/error states, but the parent SafeDataLoader pattern for nested queries (incidents + incident types) stays in the parent component.
  • Dialog triggers remain in parent. Link/unlink assessment dialogs are too specialized for DataTable. They remain as parent-level Dialog components triggered from within renderExpanded.
  • Removed ~300 lines of filter UI, pagination, and empty-state handling that DataTable now provides out of the box.
Complex Migration Notes

VerificationQueue — DataCardList migration

Current State
~375 lines. Uses useVerificationQueue and useVerificationFilters custom hooks. Manual expandedItems: Set<string> state. Inline cn() class merging for selection and hover states. Hand-built pagination with currentPage state. Separate AssessmentQueueItem sub-component (110+ lines).
Target Migration
Would use <DataCardList> with getSeverity (maps CRITICAL/HIGH/MEDIUM to severity tints), expandable=true with renderExpanded, <SearchToolbar> for search + status filter, and <PaginationBar>. The AssessmentQueueItem sub-component is eliminated entirely.
Estimated Reduction
~40% fewer lines (~225 lines)
Risk Level
Moderate
Custom hooks (useVerificationQueue, useVerificationFilters) need refactoring, but the render logic simplifies significantly. The selection ring highlight and onAssessmentSelect callback map cleanly to DataCardList props.

IncidentManagement — DataTable migration

Current State
~960 lines. Nested <SafeDataLoader> wrappers (incidents + incident types). Complex filter section with 6+ filter inputs in a Card. shadcn <Table> with manual expandedRows: Set<string> state. Expand panel shows linked assessments + linked responses + details. Dialog triggers for link/unlink assessments. Status mutation via useMutation.
Target Migration
Would use <DataTable> with expandable=true + renderExpanded, <SearchToolbar> with 6 FilterConfig entries, and actions=[Edit, Delete (destructive)]. The expanded section includes linked data inline. SafeDataLoader stays as parent wrapper.
Estimated Reduction
~30% fewer lines (~670 lines)
Risk Level
High
Complex dialogs (link/unlink assessments) with checkbox selection, async data fetching inside expand panels, and nested SafeDataLoader composition. The useMutation for status changes and router.push for navigation add coupling.
Recommendation: Migrate the table/list rendering only; keep dialog logic in the parent component. Extract handleLinkAssessmentClick, handleUnlinkAssessment, and handleLinkSelectedAssessments into a custom useIncidentAssessmentLinking hook that the parent owns. The DataTable renderExpanded callback can trigger parent-level dialog opens via a callback prop pattern. This keeps the DataTable migration scope bounded while preserving the complex interaction logic.
