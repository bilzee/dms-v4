Differences Summary
  • Each card gets a severity tint background (CRITICAL = red-50, HIGH = amber-50, MEDIUM = yellow-50) with a colored left border for instant visual prioritization
  • Cards are expandable via a chevron button, revealing full assessment details (description, gap count, needs) without navigating away
  • Metadata rendered in a consistent 3-column grid inside each card instead of a free-flowing flex layout
  • Uniform card wrapper with shadow-sm, rounded-lg, border replaces the flat border-only row approach
  • Hover state uses shadow elevation instead of background color change for a more polished interaction pattern
  • Assessment ID moved to compact monospace format alongside the action buttons for cleaner alignment

Differences Summary
  • Added a read-only indicator badge to every card, clearly communicating the donor has no edit permissions
  • "View Details" button rendered as non-actionable (disabled state) to match the read-only access level of the donor role
  • Severity tinting based on verification status instead of priority: VERIFIED = success tint, PUBLISHED = info tint
  • Replaced the separate bordered-box-per-card pattern with a unified DataCardList card wrapper with consistent shadow and spacing
  • Metadata displayed in a 3-column grid matching the assessor view for cross-role consistency
  • Removed the Card/CardHeader/CardContent wrapper overhead -- DataCardList handles card chrome internally

Differences Summary
  • All cards receive a uniform green (success) severity tint since preliminary assessments are always in Submitted status -- no mixed severity levels
  • Cards are expandable to reveal incident details (incident type, date, reporting agent) without requiring a page navigation
  • Metadata rendered in a consistent 3-column grid (location, date, assessor) replacing the two-line free-flow layout (meta + meta-secondary)
  • Standardized card wrapper with shadow-sm rounded-lg border replaces the flat bordered row approach
  • Incident reference (e.g., "FLOOD-Jun15, 2025") moved into the expanded details section to reduce visual noise in the collapsed card header
  • Consistent padding, typography, and icon sizing matches the other DataCardList instances across the application
