FormCard Component Family

Unified form wrapper, action bar, and wizard components for all DRMS data entry forms. Three components to replace 22+ ad-hoc form patterns across the codebase.

Section 02

Design Principles

Consistent chrome, flexible content

FormCard provides the wrapper -- card, title, description, action bar. The consumer provides the fields. The card shell is always the same; the fields are always custom. This separation ensures every form looks like it belongs to the same system without constraining field layout.

Standardized action patterns

Every form ends with the same Cancel + Submit button placement, sizing, and spacing. The action bar is always at the bottom, always right-aligned, always with a 12px gap. Custom buttons (Delete, Save Draft) slot in between via children.

Field approach unification

Standardize on shadcn FormField approach: react-hook-form + zod + FormField/FormItem/FormLabel/FormControl/FormMessage. FormCard does not dictate field internals -- it wraps them. But every new form should use this stack.

Progressive disclosure

Multi-step forms get a standard wizard wrapper (FormWizard). Simple forms get FormCard. Complex forms with many fields use FormCard.Section to group related fields. Each level adds complexity only when needed.

Responsive layout

Forms adapt from single-column (mobile) to two-column (desktop) via a simple columns prop. The grid uses grid-template-columns: 1fr 1fr at md breakpoint and 1fr below. Field spacing: space-y-6 for default, space-y-4 for compact.

Section 03

FormCard

Wraps a form in a Card with standardized header, spacing, and action bar. The consumer provides FormField children. FormCard handles the chrome.

interface FormCardProps { title: string description?: string variant?: "default" | "compact" | "dialog" columns?: 1 | 2 className?: string children: React.ReactNode } // Sub-components FormCard.Header // Override header content FormCard.Section // Field group with title + description FormCard.Divider // Visual separator between groups
Section 04

FormActionBar

Standardized action buttons at the bottom of every form. Renders Cancel (outline) + Submit (primary) with consistent sizing, spacing, and loading state.

interface FormActionBarProps { onCancel?: () => void cancelLabel?: string // default "Cancel" onSubmit?: () => void submitLabel?: string // default "Submit" loading?: boolean disabled?: boolean align?: "end" | "between" | "start" // default "end" variant?: "default" | "bordered" children?: React.ReactNode // Custom buttons (Delete, Save Draft) }

FormWizard

Wraps multi-step forms with a step indicator at the top and Previous/Next navigation via FormActionBar. Used for DonorRegistration, ExportModal, and similar multi-step workflows.

Section 06

Variant Selection Logic

When adding or migrating a form, follow this decision tree to determine the correct FormCard variant and wrapper:

Is the form inside a Dialog/Modal?
YES → FormCard variant="dialog" (compact padding)
NO ↓

Is the form multi-step (wizard)?
YES → FormWizard wrapping FormCard variants
NO ↓

Is the form a simple inline edit (few fields, embedded)?
YES → FormCard variant="compact"
NO → FormCard variant="default"

Variant: Default

default

Standard form card with p-6 (24px) content padding. Card header has title and optional description. Fields use space-y-6 (24px) vertical spacing. FormActionBar at the bottom with Cancel + Submit. This is the workhorse variant used for most page-level forms.

Variant: Compact

compact

Reduced padding (p-4, 16px) and tighter field spacing (space-y-4, 16px). Designed for inline edits, sidebar forms, or contexts where vertical space is limited. No card description by default.

Variant: Dialog

dialog

Compact padding optimized for modal dialogs. Renders inside a Dialog component with reduced vertical spacing. The card has no visible border (the Dialog provides the container). Content uses px-6 py-4.

Prop Type Default Description
title string -- CardHeader title. Rendered as CardTitle. Required.
description string undefined CardHeader description. Rendered as CardDescription.

columns 1 | 2 1 Field grid layout. 1 = single column always. 2 = single column mobile, two-column desktop.

Section 13

Implementation Notes

Validation integration

FormCard is presentation-only. Validation is handled by the consumer via react-hook-form + zod schemas. FormMessage renders inline below each field. FormActionBar submit button should be disabled when !form.formState.isValid.

Responsive behavior

When columns={2}, the grid uses grid-cols-1 below 768px and grid-cols-2 above. Textareas and wide fields span both columns via col-span-2. The FormActionBar always stacks buttons horizontally with flex-wrap.

Dark mode

All variants render correctly in dark mode. Cards use --card background, inputs use --input border, labels use --card-foreground. The action bar border uses --border. No additional work required by consumers.

Accessibility

Form fields must have associated labels via htmlFor / id. Required fields use aria-required="true". Error messages link to fields via aria-describedby. FormActionBar buttons have type="button" (Cancel) and type="submit" (Submit).

File structure

Components live in src/components/shared/. FormCard.tsx, FormActionBar.tsx, FormWizard.tsx. Each file is self-contained with no barrel exports. Import directly: import { FormCard } from '@/components/shared/FormCard'.

Composability

FormCard does not wrap <form> itself. The consumer provides <form> around or inside FormCard. This allows FormCard to work inside Dialog components, existing form providers, or as a nested sub-form within a larger page.

Section 14

Error State Rendering

When a field fails validation, the FormField (from shadcn) renders an error state. FormCard does not control this -- it just provides the container. The standard pattern is: red border on input, red error text below, aria-describedby linking input to error.
