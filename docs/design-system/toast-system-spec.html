Section 01

Toast System Consolidation

Standardize on a single toast library (Sonner) to replace the current dual-system approach. Two toast implementations coexist today -- Sonner (14 files) and Radix UI Toast via shadcn (2 files). This spec documents the migration to a single, unified system.

Current State: Dual System

The DRMS codebase currently uses two incompatible toast notification systems. This creates inconsistency in appearance, behavior, and API surface across the application.

Section 02

Decision: Standardize on Sonner

Verdict: Migrate all toast calls to Sonner, remove Radix toast

Sonner is already the majority system (14 vs 2 files) and shadcn/ui itself now recommends Sonner over the Radix toast component. The migration involves only 2 trivial call-site changes and 3 file deletions.

1. Sonner is the majority system

14 files already use Sonner vs only 2 using Radix. Migrating 2 files is far cheaper than migrating 14.

2. Simpler API surface

toast.success(msg) vs useToast() + toast({ title, variant }). No hooks, no context, no provider -- just import and call.

3. Rich type support built-in

Native toast.success(), toast.error(), toast.warning(), toast.info(), toast.promise() -- no custom variant mapping needed.

4. Better UX out of the box

Built-in stacking, auto-dismiss, swipe-to-close, and promise tracking. No custom implementation needed.

5. shadcn/ui recommends Sonner

The shadcn/ui project itself now recommends Sonner over the Radix toast component. Aligning with upstream reduces maintenance burden.

Section 03

Sonner API Reference

Function Signatures

// Basic types toast.success(title: string, options?: ExternalToast) => string | number toast.error(title: string, options?: ExternalToast) => string | number toast.warning(title: string, options?: ExternalToast) => string | number toast.info(title: string, options?: ExternalToast) => string | number toast.loading(title: string, options?: ExternalToast) => string | number toast.dismiss(id?: string | number) => void // Promise tracking (auto loading -> success/error) toast.promise( promise: Promise<T>, opts: { loading: string success: string | ((data: T) => string) error: string | ((err: Error) => string) } )

Options Object

Option Type Default Description
description string - Subtitle text displayed below the title.
duration number 4000 Auto-dismiss in ms. Use Infinity for persistent toasts.
position string 'top-right' Override global position for this specific toast.
dismissible boolean true Allow manual dismiss via swipe or close button.
action { label, onClick } - Action button rendered inside the toast.
cancel { label, onClick } - Cancel button rendered inside the toast.
id string auto Custom ID for updating or dismissing an existing toast.
icon ReactNode auto Custom icon to replace the default type icon.

Toaster Configuration

// Mount in layout.tsx (replace Radix Toaster) import { Toaster } from 'sonner' <Toaster richColors {/* auto-colors based on type */} position="top-right" duration={4000} closeButton {/* X button on each toast */} toastOptions={{ className: '...' {/* custom overrides */} }} />
Section 04

Standardized Toast Patterns

Pattern 1: Success Feedback

Use after successful CRUD operations -- record creation, updates, deletions.

// Simple success toast.success('Commitment created successfully') // Success with description toast.success('Profile updated', { description: 'Your changes have been saved' })

Pattern 2: Error Feedback

Use after failed API calls, validation errors, or unexpected exceptions.

// Simple error toast.error('Failed to create commitment') // Error with description toast.error('Sync failed', { description: 'Check your connection and try again' })

Pattern 3: Warning

Use for non-blocking issues, degraded functionality, or important notices.

toast.warning('Connection lost', { description: 'Changes will be saved locally', duration: 5000 })

Pattern 4: Promise (Async with Progress)

Use for long-running operations with automatic loading, success, and error states.

toast.promise( saveData(), { loading: 'Saving changes...', success: 'Changes saved', error: 'Failed to save' } )

Pattern 5: With Action Button

Use for undo operations, retry suggestions, or secondary actions.

toast.error('Delete failed', { action: { label: 'Retry', onClick: () => handleDelete() } })

Section 08

Migration Steps

1

Mount Sonner Toaster in layout.tsx

Replace the Radix <Toaster /> in src/app/layout.tsx with Sonner's <Toaster />.

// src/app/layout.tsx import { Toaster } from '@/components/ui/toaster' import { Toaster } from 'sonner' // Inside the layout return: <Toaster /> <Toaster richColors position="top-right" closeButton />
2

Migrate roles/page.tsx

Replace useToast hook with direct Sonner import. The toast call changes from an object signature to a typed method.

// src/app/(auth)/admin/roles/page.tsx import { useToast } from '@/components/ui/use-toast' import { toast } from 'sonner' // Inside the component: const { toast } = useToast() // Replace the toast call: toast({ title: 'Error', description: 'Failed to delete role', variant: 'destructive' }) toast.error('Failed to delete role')
3

Migrate donor/reports/page.tsx

Same pattern as Step 2. Replace the hook-based toast with a direct Sonner call.

// src/app/(auth)/donor/reports/page.tsx import { useToast } from '@/components/ui/use-toast' import { toast } from 'sonner' // Inside the component: const { toast } = useToast() // Replace the toast call: toast({ title: 'Error', description: '...', variant: 'destructive' }) toast.error('Failed to generate report')
4

Delete Radix toast files

Remove the now-unused Radix toast component files. If no other package depends on @radix-ui/react-toast, remove it from package.json as well.

# Delete files rm src/components/ui/toast.tsx rm src/components/ui/use-toast.ts rm src/components/ui/toaster.tsx # Optionally remove unused dependency npm uninstall @radix-ui/react-toast
